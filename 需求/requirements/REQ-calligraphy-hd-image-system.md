# REQ-CALLIGRAPHY-HD-IMAGE-SYSTEM：书法高清大图系统需求规格书

> **版本**：V1.2  
> **状态**：需求已确认，待技术方案设计与开发  
> **更新日期**：2026-08-03

## 1. 背景与目标

本系统面向手机与 PAD 端，为书法高清长卷提供基于 Web 瓦片的浏览资源和导航数据。每件作品最多提供三种视觉版本：原图、黑白图和书法双钩图；移动端通过统一 Manifest 获取各版本的瓦片地址、共享的图层信息及原图缩略图导航信息。

系统产出永久保存的图片文件和 JSON 数据；不包括后台在线服务、移动端接口实现或移动端页面实现。黑白图生成、双钩图生成和人工评审可独立实现、独立部署，但其产物必须遵守本规格定义的统一资源与坐标契约。

### 1.1 目标

- 支持以 Web 瓦片浏览典型尺寸为 80000×5000 像素的书法高清大图。
- 支持原图、黑白图、书法双钩图在同一 `(z, x, y)` 坐标下定位同一视觉区域。
- 提供仅基于原图生成的 9:16 缩略图和 `jump2x` 导航锚点。
- 保留从 HTTP 来源、下载文件、拼接大图、候选图、人工选择到已发布资产的可追溯信息。
- 所有正式资产可迁移至同一个阿里云 OSS 根前缀，并支持数千件作品长期保存。

### 1.2 非目标

- 不定义移动端页面、瓦片加载策略、缓存策略或移动端接口实现。
- 不定义双钩图的具体图像算法、轮廓提取方式、线宽或形态学参数。
- 不在当前阶段定义数据库、消息队列、异步任务框架或 OSS 上传程序。
- 不以本需求固定 JPEG 质量、性能 SLO；这些应在后续技术方案中确定。

## 2. 术语与领域对象

| 术语 | 定义 |
|---|---|
| 原始来源图片 | HTTP 地址列表中的一项图片资源。 |
| 下载文件 | 由原始来源图片下载并归档的本地 JPG、PNG 或 TIF 文件。 |
| 分屏图 | 同一作品按书写长卷方向分段拍摄或获取的多个下载文件。 |
| 拼接高清大图 / 原图 | 单图模式的下载文件，或按规定顺序拼接的分屏图，作为后续处理的统一画布。 |
| 黑白候选 | 对原图使用一组参数生成、尚未人工确认的黑白图。 |
| 已选黑白图 | 人工从黑白候选中确认、可进入正式发布流程的唯一黑白图。 |
| 双钩候选 | 基于已选黑白图生成、尚未人工确认的书法双钩图。 |
| 已选双钩图 | 人工从双钩候选中确认、可进入正式发布流程的唯一双钩图。 |
| 瓦片集 | 某个正式版本按统一金字塔规则生成的 JPEG 瓦片文件集合。 |
| 缩略图 | 仅根据原图生成、用于移动端快速定位的 9:16 导航图。 |

| 作品级 version_id | 一件作品（一套处理任务）的唯一标识，用于存储分区与 Manifest；由任务参数提供。 |

术语“书法双钩图”是本项目唯一标准用语；历史材料中的“**双构图**”均指书法双钩图。

## 3. 范围、组件与处理流程

### 3.1 组件边界

| 组件 | 职责 | 边界 |
|---|---|---|
| 获取与归档模块 | 读取 HTTP 地址列表、下载文件、记录来源和校验结果 | 输出本地单图或有序分屏图，不负责移动端服务。 |
| 原图拼接与导航模块 | 拼接分屏图、生成原图瓦片、缩略图和原始位置映射 | 产出原图正式资产。 |
| 黑白图生成模块 | 生成 2–10 个黑白候选 | 独立程序；不直接发布候选。 |
| 双钩图生成模块 | 基于已选黑白图生成 2–10 个双钩候选 | 独立程序；不定义具体算法。 |
| 人工评审工具 | 对单件作品的候选进行细节比较、选择和确认 | 独立 standalone 工具，不属于移动端瓦片 API。 |
| 瓦片与 Manifest 装配模块 | 对各正式版本生成瓦片、装配统一 Manifest | 仅发布已满足本规格的正式资产。 |

### 3.2 端到端流程

```text
HTTP 地址列表
  → 下载并归档原始来源图片
  → 单图直接作为原图 / 多图按列表顺序从右向左拼接为原图
  → 生成原图瓦片、缩略图、导航锚点和原图位置映射
  → 生成黑白候选（2–10 个）→ 人工选择 → 生成已选黑白图瓦片
  → 基于已选黑白图生成双钩候选（2–10 个）→ 人工选择 → 生成已选双钩图瓦片
  → 装配并发布统一 Manifest
```

候选图在整套作品完成人工选择与处理前必须保留；整套处理完毕后，未选候选可不再保留（见 §9.1）。无论保留与否，候选图均不得作为移动端正式版本在 Manifest 的 `url_template_bw` 或 `url_template_hook` 中发布。

## 4. 输入、下载与归档

### 4.1 输入

- 输入为 HTTP 图片地址列表的 JSON 清单文件（实测样例：`deepseek_json_20260731_ba67e1.json`）。
- 清单为 JSON 数组，每项包含：
  - `img_id`：来源图唯一标识（实测为 UUID）。
  - `source_url`：原始 HTTP 地址。
  - `img_num`：来源图顺序号，1 起始；多图拼接的权威排序字段。
- 清单数组本身有序，但排序必须以 `img_num` 为准（实测样例中 `img_num` 顺序与 URL 文件名顺序不一致）。
- 支持的图片格式为 JPG、PNG、TIF。
- 下载后的本地文件按以下两种模式处理：
  - **单图模式**：清单仅含 1 个来源项，下载文件即一张原图。
  - **多图模式**：清单含 2 个及以上来源项，同一作品的多个下载文件组成有序分屏图列表。
- 典型目标画布尺寸为宽×高 `80000×5000` 像素；这也是黑白图处理的当前系统约束。具体作品尺寸以实际下载和拼接结果为准。

### 4.2 来源与处理记录

每个来源项必须至少记录：

- `source_index`：在 HTTP 地址列表中的 1 起始位置。
- `img_id`：来源图唯一标识（来自输入清单）。
- `source_url`：原始 HTTP 地址。
- 下载结果：成功或失败、失败原因、下载时间。
- 本地归档文件标识、原始文件名、格式、像素宽高。
- 文件可读性、格式和尺寸校验结果。
- 多图模式下，该分屏图在拼接原图中的物理 X 区间 `[x_start, x_end)`。
- 拼接原图的最终宽高和生成状态。

### 4.3 尺寸一致性处理与失败处理

**分屏图尺寸一致性检查**（多图模式）：拼接前必须检查所有分屏图的尺寸兼容性。

- 若各分屏图**高度不一致**，不直接判失败，而是执行**统一到最小公共高度**的等比例缩放：
  - 取所有分屏图高度的最小值 `min_h` 作为统一高度。
  - 每张分屏图等比例缩放至高度 `min_h`（宽度按比例调整），使用高质量重采样以最小化质量损失。
  - 统一后的分屏图作为拼接输入，原始分屏图仍永久归档。
  - 来源记录须标注该分屏图是否经过缩放、原始尺寸与统一后尺寸。
- 仍判为失败、停止处理且不发布 Manifest 的情况：
  - 来源下载失败。
  - 下载文件不可读取、格式不受支持或校验失败。
  - 处理后尺寸不符合本次任务配置的有效范围。

注：分屏图方向不一致（横向与纵向混用）时，仍按统一最小公共高度等比缩放后拼接，不判失败；缩放后内容比例由原图决定，业务侧确认接受。

失败原因必须关联到来源项或处理阶段；修复输入后允许重新处理。

## 5. 原图拼接、坐标与来源位置映射

### 5.1 多图拼接

- 多图模式必须严格以 HTTP 地址列表顺序（或清单的 `img_num` 顺序）为权威顺序。
- 列表第 1 个分屏图位于拼接原图的最右侧；最后一个分屏图位于最左侧，即物理拼接方向为从右向左。
- 拼接前按 §4.3 统一各分屏图高度至最小公共高度（等比缩放），统一后的图参与拼接。
- 拼接与原图生成过程中，唯一允许的缩放是 §4.3 的高度统一等比缩放；不得进行拉伸或改变内容比例。
- 拼接生成的最终画布尺寸即正式版本尺寸；原图、黑白图、双钩图均保持该原始大小，不做额外缩放。
- 拼接完成后，原图左上角为全局原点 `(0, 0)`，X 向右递增，Y 向下递增。
- 单图模式同样使用上述全局坐标系，其下载文件即拼接原图。

### 5.2 原始列表位置与瓦片位置映射

系统必须为每张分屏图建立可追溯的导航映射，至少包含：

- `source_index` 与其在拼接原图中的 `[x_start, x_end)` 物理 X 区间。
- 在每个 `z` 层，该物理 X 区间覆盖的 tile-X 索引范围。
- 该分屏图的物理中心点及其每个 `z` 层的 tile-X 索引。

映射使用与 Manifest 及所有瓦片集完全相同的坐标系。该数据供后续定位、校验和接口扩展使用；其最终 JSON 字段名称由技术方案确定。

## 6. 黑白图与书法双钩图

### 6.1 黑白图

- 输入为拼接完成的原图。
- 每次必须生成 **2–10 个**有不同参数或策略标识的黑白候选。
- 每个候选必须记录候选标识、生成参数或策略标识、生成时间和文件路径。
- 只有人工确认的一个候选可成为已选黑白图并进入正式瓦片生成。
- 已选黑白图必须与原图保持完全相同的画布宽高和像素坐标，不得裁切、缩放或平移。

已选黑白图必须满足以下强制质量边界：

- 输出为二值白底黑字图。
- 书法笔画和印章均为黑色前景，像素值为 `0`。
- 背景为白色，像素值为 `255`。
- 带红色印章的来源图中，印章必须归入黑色前景。
- 黑底白字来源图必须检测并统一为白底黑字输出。
- 上述 `0`/`255` 严格二值约束适用于已选黑白图 master 文件（PNG）；对外瓦片为 JPEG，允许有损压缩导致像素值偏离（见 §7.1）。

`D:\wordspaces\claudeCode\gaoqing\heibai20260630` 仅作为黑白图算法和质量目标的参考；其中的 `50000×4000` 尺寸限制和 `3–20` 候选数量不适用于本系统。

### 6.2 书法双钩图

- 输入必须为已选黑白图，不得直接以原图或未选黑白候选作为正式双钩图输入。
- 每次必须生成 **2–10 个**双钩候选，并记录候选标识、参数或策略标识、生成时间和文件路径。
- 人工确认的一个候选成为已选双钩图；只有已选双钩图可以进入正式瓦片生成和 Manifest 发布。
- 已选双钩图必须与已选黑白图、原图保持完全相同的画布宽高和像素坐标，不得裁切、缩放或平移。
- 双钩图的具体图像处理算法和质量量化指标由后续技术方案定义，不在本需求中预设。

### 6.3 版本生命周期

原图、黑白图和双钩图分别维护以下状态；状态和错误原因作为内部处理记录保存：

| 状态 | 含义 | Manifest 行为 |
|---|---|---|
| `not_generated` | 尚未开始生成 | 对应衍生版本 URL 模板为空字符串。 |
| `generating_candidates` | 正在生成候选 | 对应衍生版本 URL 模板为空字符串。 |
| `pending_selection` | 候选已生成，等待人工选择 | 对应衍生版本 URL 模板为空字符串。 |
| `selected` | 已选定正式图，但尚未完成瓦片 | 对应衍生版本 URL 模板为空字符串。 |
| `generating_tiles` | 正在生成正式瓦片 | 对应衍生版本 URL 模板为空字符串。 |
| `published` | 正式图、瓦片和校验均已完成 | 返回对应 URL 模板。 |
| `failed` | 生成、选择确认或瓦片生成失败 | 对应衍生版本 URL 模板为空字符串。 |

原图在原图瓦片、缩略图、导航数据和原图模板均通过校验前不得发布 Manifest。

## 7. 瓦片集规范

### 7.1 统一坐标与金字塔

- 固定瓦片尺寸：`256×256` 像素。
- 坐标原点为原图左上角 `(0, 0)`；X 向右递增，Y 向下递增。
- 金字塔从全局最小缩放层 `Z=0` 生成到原始像素分辨率层 `Z=Zmax`。
- `Zmax` 层必须保留原图的像素分辨率，不得为降低分辨率而缩放原图。
- 瓦片对外 URL 使用 `.jpg`；JPEG 编码质量由技术方案确定。这里的原始分辨率要求不等同于 JPEG 文件无损或不压缩。

### 7.2 三版本严格一致性

原图、已选黑白图和已选双钩图的正式瓦片集必须使用同一：

- 最终画布宽高。
- `(0, 0)` 原点和 X/Y 方向。
- `tile_size`。
- `Z=0...Zmax` 层范围与缩放规则。
- 每层 `tile_count_x` 与 `tile_count_y`。
- `(z, x, y)` 取址含义。

因此，当三种版本均已发布时，对任意合法 `(z, x, y)`，三个瓦片都表示原图上同一物理视觉区域。该要求不代表三张瓦片的像素值相同。

## 8. 缩略图与导航锚点

### 8.1 通用规则

- 缩略图仅从原图生成，永久保存，三种版本共用。
- 每张缩略图必须为 `9:16` 宽高比。
- 当对应区域高度不足 `1920` 像素时不做特殊处理（不放大、不填充、不强制裁切），按实际高度输出，此时不强制 `9:16`。
- 长卷最右侧为阅读起点，其缩略图 `index` 为 `1`；向左 `index` 依次递增。
- Manifest 中 `thumbnails` 必须按 `index` 倒序输出，即最大 `index`（最左侧）排在数组首项，`index: 1`（最右侧）排在末项。

### 8.2 单图模式

- 从原图最右侧开始，以固定宽度 `1080` 像素向左分段。
- 在每段对应的视觉区域中心生成 `1080×1920` 的 9:16 缩略图。
- 当左端剩余宽度不足 `1080` 像素时，最后一页强制取 X 区间 `[0, 1080]`；允许与前一页重叠。
- 原图高度不足 `1920` 像素时不做特殊处理：不放大、不填充、不强制裁切，缩略图按实际高度输出（§8.1 例外）。

### 8.3 多图模式

- 每张原始分屏图对应一张缩略图。
- 分屏图非 9:16 时，以其物理中心为中心裁取 9:16 区域。
- 该缩略图对应的原图物理区域必须来自该分屏图在拼接原图中的 X 区间。
- 分屏图区域高度不足 `1920` 像素时，处理策略与单图模式相同：不做特殊处理，按实际高度输出。

### 8.4 `jump2x`

- 每张缩略图取其对应原图区域的物理中心 X 坐标。
- 必须将该中心点换算为从 `Z=0` 到 `Z=Zmax` 每一层对应的 tile-X 索引，形成 `jump2x` 数组。
- `jump2x` 必须包含每一层各一项，且索引在该层合法 tile-X 范围内。

## 9. 存储对象键与永久保存

### 9.1 存储原则

- 原图、已选黑白图、已选双钩图、瓦片图、缩略图、Manifest 和处理记录均为永久资产。
- 候选图保留策略：人工选择完成前，全部候选全分辨率保留；整套作品全部来源图完成选择且处理完毕后，未选候选可不再保留，已选候选及其参数/策略记录永久保留。
- 所有对象位于同一存储根前缀（例如 `/storage`）下，并以作品级 `version_id` 分区，便于整体迁移至同一个 OSS bucket/prefix。
- 允许对象键使用 `/` 层级以表达瓦片金字塔；这表示统一根前缀下的可预测对象键，不表示多个 bucket 或分散存储目录。

### 9.2 正式资产对象键

```text
/storage/{version_id}/source/{source_index}.{ext}      # 下载归档的来源文件
/storage/{version_id}/original.jpg                     # 拼接高清大图 / 原图
/storage/{version_id}/bw/selected.png                  # 已选黑白图
/storage/{version_id}/hook/selected.png                # 已选书法双钩图
/storage/{version_id}/thumbs/{index}.jpg               # 原图缩略图
/storage/{version_id}/tiles/original/{z}/{x}_{y}.jpg   # 原图瓦片
/storage/{version_id}/tiles/bw/{z}/{x}_{y}.jpg         # 已选黑白图瓦片
/storage/{version_id}/tiles/hook/{z}/{x}_{y}.jpg       # 已选双钩图瓦片
/storage/{version_id}/manifest.json                    # 移动端 Manifest
/storage/{version_id}/records/processing.json          # 来源、状态、选择和失败记录
```

候选对象键必须包含版本类型、候选标识及必要的参数/策略标识，具体命名由技术方案确定。

## 10. 移动端 Manifest 契约

### 10.1 发布条件

Manifest 仅在原图瓦片、缩略图、图层信息和导航数据均已校验通过后发布。黑白图和双钩图的 URL 模板只在对应版本状态为 `published` 时返回有效字符串；其他状态一律返回空字符串 `""`。

### 10.2 JSON 示例

示例中的 `max_z`、图层瓦片数量和缩略图数均为示意值；实际值必须由该作品的最终尺寸和统一金字塔规则计算。

```json
{
  "manifest_version": 1,
  "version_id": "20260611_HD_LONG_SCROLL_001",
  "orig_width": 80000,
  "orig_height": 5000,
  "max_z": 4,
```

### 10.3 字段规则

- `version_id`：作品级唯一标识，与存储分区键一致。
- `manifest_version`：Manifest schema 版本号，当前为 `1`；移动端据此做兼容判断。
- `url_template`：原图瓦片模板；原图发布后必须为非空字符串。
- `url_template_bw`：已选黑白图瓦片模板；未发布时必须为 `""`。
- `url_template_hook`：已选书法双钩图瓦片模板；未发布时必须为 `""`。
- `layers`：三个版本共用，只返回一次。
- `thumbnails`：仅原图缩略图，按 `index` 倒序；所有版本共用。

## 11. 人工评审工具

人工评审工具是独立 standalone 工具，不属于移动端瓦片服务接口。它必须满足：

- 针对单一作品展示同一类型的 2–10 个候选（黑白候选或双钩候选）。
- 支持候选之间的并排比较、缩放和细节查看。
- 支持与原图或上游正式图按照同一物理坐标进行对照。
- 支持确认唯一最优候选。
- 选择确认后，记录候选标识、参数/策略标识、文件路径、选择时间和操作者标识；随后触发或允许触发正式瓦片生成。
- 未确认选择时，不得将候选作为已发布版本输出至 Manifest。

## 13. 验收标准

| 编号 | Given | When | Then |
|---|---|---|---|
| AC-01 | 一份 HTTP 地址列表 | 执行获取流程 | 每个来源项均记录顺序、URL、下载结果、文件格式、像素尺寸和校验结果。 |
| AC-02 | 含多个分屏图的有序列表 | 执行拼接 | 第 1 项位于原图最右侧，最后一项位于最左侧，且原图左上为 `(0, 0)`。 |
| AC-03 | 已拼接的多图原图 | 生成来源位置映射 | 每张分屏图均有物理 X 区间、各层 tile-X 覆盖范围和中心点 tile-X 映射。 |
| AC-04 | 各分屏图高度不一致的作品 | 执行尺寸一致性处理 | 各分屏图等比缩放至最小公共高度（高质量重采样，最小化质量损失），统一后拼接；来源记录标注缩放与原始/统一尺寸。 |
| AC-04b | 下载失败或文件不可读的作品 | 执行处理 | 保留阶段/来源失败原因，停止后续处理，且不发布 Manifest。 |
| AC-05 | 尺寸为 80000×5000 的有效原图 | 生成黑白候选 | 能输出 2–10 个带候选标识和参数/策略标识的候选，不以旧项目的 50000×4000 限制阻断。 |
| AC-06 | 带红色印章、黑底白字或正常纸本的原图 | 确认黑白图 | 已选黑白图为原图同尺寸同坐标的二值白底黑字图，背景为 255，笔画与印章为 0。 |
| AC-07 | 已选黑白图 | 生成和选择双钩候选 | 输出 2–10 个候选；选定图与原图保持同尺寸、同坐标，且不要求特定双钩算法。 |
| AC-08 | 原图、已选黑白图和已选双钩图 | 生成正式瓦片 | 三套瓦片的 tile size、Z 范围、每层网格及 `(z,x,y)` 所表示的物理区域完全一致。 |
| AC-09 | 黑白图或双钩图未发布 | 输出 Manifest | 对应 `url_template_bw` 或 `url_template_hook` 精确为 `""`，不得指向候选或未完成瓦片。 |
| AC-10 | 三种版本均发布 | 输出 Manifest | `layers` 仅出现一次；三个 URL 模板使用同一 `z/x/y` 坐标契约。 |
| AC-11 | 单图模式的原图 | 生成缩略图 | 从右向左按 1080px 步长生成 9:16 缩略图；左端不足 1080px 时使用 `[0, 1080]`，允许重叠。 |
| AC-12 | 多图模式的原图 | 生成缩略图 | 每个分屏图对应一张缩略图，非 9:16 时按物理中心裁取；最右侧 `index` 为 1。 |
| AC-13 | 任一缩略图 | 生成 `jump2x` | 数组覆盖 `Z=0...Zmax` 的全部层级，且每项 tile-X 处于该层合法范围。 |
| AC-14 | 多张缩略图 | 输出 Manifest | `thumbnails` 严格按 `index` 倒序输出。 |
| AC-15 | 黑白或双钩候选 | 在独立评审工具中确认选择 | 可以缩放和并排对比；选择记录包含候选标识、参数/策略、路径和选择时间。 |
| AC-16 | 已发布作品的正式资产 | 存储或迁移至统一 OSS 根前缀 | 对象键可由 `version_id`、版本和瓦片坐标预测，且原图、衍生图、缩略图、Manifest 和处理记录均可定位。 |

以下目标在技术方案阶段补充可量化指标后验收：移动端“流畅查看”、缩略图“快速定位”、数千件作品的批量吞吐和存储容量、JPEG 编码质量、双钩图质量指标。

## 15. 本版本已确认与待定项

### 15.1 已确认

- HTTP 地址列表下载后作为本地单图或有序分屏图输入。
- 多图按列表顺序从右向左拼接。
- 原图、黑白图、书法双钩图共用瓦片坐标、图层和缩略图导航数据。
- 黑白和双钩各生成 2–10 个候选，由独立人工评审工具选择。
- 黑白正式图必须符合白底黑字、笔画/印章为 0、背景为 255 和极性统一要求。
- 最大层保留原始像素分辨率，瓦片 URL 采用 JPEG。
- 输入清单契约：JSON 数组，字段 `img_id`、`source_url`、`img_num`；`img_num` 为多图拼接权威排序字段。
- 原图、黑白图、双钩图均保持拼接原图的原始大小，拼接时仅允许等比例缩放。
- 缩略图对应区域高度不足 1920 像素时不做特殊处理，按实际高度输出。
- 作品级标识定名为 `version_id`（由任务参数提供）；来源图 `img_id` 仅作来源追溯。
- 候选图保留策略：选择完成前全部保留，整套处理完毕后未选候选可删除。
- Manifest 包含 `manifest_version` 字段（当前为 1）。
