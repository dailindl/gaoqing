
# 📄 高清大图瓦片化与导航 API - 最终需求规格书 (V1.0 Final)

## 一、 运行环境与架构边界

- **技术栈**：Python 3.11+, FastAPI。
    
- **环境隔离**：严格运行在 Conda 虚拟环境 `zgy_hd_py311` 内，无全局依赖污染。
    
- **持久化**：纯内存/文件流处理，当前阶段**不引入任何数据库**。
    

## 二、 核心图像处理与坐标系

- **输入模式**：支持“本地单张高清大图”或“本地多张分屏图”上传。
    
- **拼图规则（多图模式）**：严格按文件列表顺序，**从右向左**进行物理拼接。即：列表第 1 个文件拼接在最右侧，最后一个文件拼接在最左侧。
    
- **坐标系标准**：遵循标准 Web 瓦片地图坐标系。大图合并完毕后，**左上角为原点 (0, 0)**。X 轴向右递增，Y 轴向下递增。
    

## 三、 Web 瓦片切割逻辑 (Web Tiles)

- **切片标准**：将合并后的大图切割为正方形的 Web 瓦片图（Tile Size 固定为 256x256）。
    
- **金字塔层级**：从全局缩放的最小图层（Z=0）生成至 1:1 原始分辨率的最底层（Z=Zmax）。
    

## 四、 缩略图生成与索引流 (Thumbnails)

**业务目标**：支撑 APP 端（兼容手机与 PAD）底部的“胶卷导航 (Filmstrip) / 小地图”，用于快速定位高清大图。

- **画幅约束**：所有下发的缩略图必须严格保持 **9:16** 的宽高比。
    
- **命名与排序方向**：
    
    - 遵循传统长卷“从右向左”阅读习惯，大图的**最右侧为阅读起点**。
        
    - 最右侧的缩略图 `index` 定义为 1，向左依次递增。
        
    - API 最终输出的 `thumbnails` 数组必须按 `index` **倒序**排列（从最左侧的最大页数开始，以最右侧的 index 1 结束）。
        
- **多图模式生成规则**：
    
    - 一张原始分屏图对应生成一个缩略图。
        
    - **容错截取**：若原始分屏图比例非 9:16，则以原图**物理中心点**向外扩散，截取 9:16 的中心区域作为缩略图。
        
- **单图模式生成规则（全局固定步长）**：
    
    - **切分步长**：采用强兼容性的全局绝对常数，固定宽度 **W = 1080 像素**。
        
    - **倒序切分**：从大图最右侧边界开始，每次向左移动 1080 像素划定切片区域。在该区域内取中心截取 1080×1920 (9:16) 的画面生成缩略图。
        
    - **边缘重叠容错**：当向左切至最左侧（卷首）时，若剩余宽度不足 1080 像素，最后一页缩略图（即 index 最大的那一页）强制以大图最左侧原点 X=0 为基准，向右截取 [0, 1080] 区间。允许在视觉上与前一页有物理重叠，以保证画幅不被破坏。
        

## 五、 导航锚点映射 (jump2x)

- **锚点取值**：取当前缩略图对应的画面区域在总大图 X 轴上的**物理中心点坐标**。
    
- **层级映射**：计算该物理中心点在不同缩放比例下，从 Z=0 到 Z=Zmax 层级所对应的瓦片矩阵横向索引（Tile X），构建 `jump2x` 数组。
    

## 六、 API 输出契约与 JSON 示例

**API 目标**：提供给原生 APP 调用的接口，一次性返回完整大图清单（Manifest）。
